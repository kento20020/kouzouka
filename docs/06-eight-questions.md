# 06 異常系を出す「8つの問い」

ユースケースの**各ステップ**と、状態×イベント表の**各行**に、この問いを当てていきます。
問いの答えが「表の列（イベント）」になり、列が増えれば、自動的にマスが増えます。

## 8つの問い

| # | 問い | 具体的に確かめること | 「AIに送る」での例 |
| --- | --- | --- | --- |
| ① | **2回起きたら？** | 連打・再送・複数タブ・2台の端末で同時に操作・通知の二重受信・Webhook の二重配信 | 送信ボタンの連打、ケースBの再試行、PCとスマホで同時に送信 |
| ② | **途中で止まったら？** | 切断・アプリの強制終了・タイムアウト・電池切れ・OS によるプロセス終了・サーバーの再起動 | 送信中に機内モード、受信中にアプリを上スワイプで終了 |
| ③ | **0件／1件／大量なら？** | 空の状態・ページ分け・上限・1件だけのときの表示・大量のときの速さ | 履歴0件の初回画面、1万件の履歴、10万文字の回答 |
| ④ | **遅かったら？** | 3秒なら？30秒なら？何秒でタイムアウトにする？遅いときに何を見せる？ | 最初の1文字まで20秒かかる。その間「考え中」を見せるか |
| ⑤ | **別の人なら？** | 未ログイン・権限なし・他人のデータID・管理者・退会済みユーザー・招待前のユーザー | 他人の会話IDを URL に入れて開く、無料プランの人が有料機能を使う |
| ⑥ | **順番が違ったら？** | URL直打ち・戻る・通知から起動・手順の飛ばし・応答が送った順に返ってこない | 2回目の質問の回答が、1回目より先に届く |
| ⑦ | **外部サービスが壊れたら？** | 失敗・遅延・おかしな出力・回数制限・利用上限・仕様変更・メンテナンス | AI API が 429、0文字の回答、途中で文字化け、モデルの提供終了 |
| ⑧ | **時間が経ったら？** | ログインの有効期限切れ・日付の切り替わり・古いキャッシュ・放置してから戻ってきた・サマータイム・月末 | 送信画面を開いたまま一晩放置してから送信、日付をまたいで利用回数がリセット |

これに次の2系統を足せば、ほぼ網羅できます。

### 入力系

| 観点 | 例 |
| --- | --- |
| 空 | 未入力、空白だけ、改行だけ |
| 長すぎ | 上限ちょうど・上限＋1文字（境界値）、貼り付けで一気に10万文字 |
| 文字の種類 | 絵文字（👨‍👩‍👧 は1文字に見えて複数の符号）、全角／半角、機種依存文字、右から左に書く文字 |
| 形式違い | メールアドレス・電話番号・日付の形式、前後の空白 |
| 悪意 | HTML・スクリプト（`<script>`）、SQL の断片、AIへの指示の乗っ取り（プロンプトインジェクション） |
| ファイル | 0バイト、巨大なファイル、拡張子と中身が違う、画像の向き情報（回転して表示される） |

### 環境系

| 観点 | 例 |
| --- | --- |
| アプリのバージョン | 古いアプリが新しいAPIを呼ぶ、強制アップデートが必要か |
| OS のバージョン | 古い OS で使えない機能、OS ごとの戻るの挙動の違い |
| 回線 | 遅い回線、不安定な回線（つながったり切れたり）、Wi-Fi⇔モバイル回線の切り替わり |
| 画面 | 画面回転、文字サイズを最大にした設定、小さい画面、折りたたみ端末、ダークモード |
| 端末の状態 | 容量不足、低電力モード、通知をオフにしている、権限（カメラ・写真）を拒否している |
| 言語・地域 | 端末の言語、タイムゾーン、日付の書式 |

## 使い方

1. ユースケースの基本フローを1ステップずつ見る
2. そのステップに8つの問いを順に当てる（1ステップ1〜2分でよい）
3. 「起こりうる」と思ったものを、状態×イベント表の**列（イベント）**として追加する
4. 追加した列について、全行（全状態）のマスを埋める

```
基本フロー 2. ユーザーが送信する
  ① 2回起きたら？     → 列「連打」「別端末から同時送信」を追加
  ② 途中で止まったら？ → 列「切断」「アプリが裏へ」を追加
  ⑤ 別の人なら？       → 列「セッション切れ」を追加
  ⑦ 外部が壊れたら？   → 列「AIが429」「AIが0文字」を追加
  ⑧ 時間が経ったら？   → 列「一晩放置してから送信」を追加（＝セッション切れと同じ扱いでよいか確認）
```

問いを当てるのは「列を増やすため」であり、思いついた異常系を1つずつ個別に対処するためではありません。
**列を1つ増やすと、全状態に対して「そのイベントが来たら？」を考えることになる**ので、漏れが減ります。

## 8つの問いは HAZOP のガイドワードと同じ発想

化学プラントなどの安全分析で使われる HAZOP（ハゾップ）は、決まった言葉（ガイドワード）を工程の各段階に当てて「設計からのずれ」を洗い出します。
8つの問いは、これをソフトウェア向けに言い換えたものと見ることができます。

| HAZOP のガイドワード | 意味 | 対応する問い |
| --- | --- | --- |
| NO／NOT（無い） | 起きるはずのことが起きない | ② 途中で止まったら、③ 0件なら |
| MORE（多い） | 量・回数が多い | ① 2回起きたら、③ 大量なら |
| LESS（少ない） | 量・回数が少ない | ③ 1件なら、⑦ おかしな出力（0文字） |
| PART OF（一部だけ） | 一部しか起きない | ② 途中で止まったら（途中までの回答） |
| REVERSE（逆） | 逆の操作 | ⑥ 戻る、キャンセル |
| OTHER THAN（別のもの） | 想定と違うものが来る | ⑤ 別の人なら、⑦ 外部が壊れたら |
| EARLY／LATE（早い／遅い） | タイミングのずれ | ④ 遅かったら、⑧ 時間が経ったら |
| BEFORE／AFTER（前／後） | 順番のずれ | ⑥ 順番が違ったら |

## 他のヒューリスティック（発想の手がかり）

- **Test Heuristics Cheat Sheet**（Elisabeth Hendrickson ほか）：探索的テストの発想集。「0・1・たくさん」「大きすぎ・小さすぎ・ちょうど（ゴルディロックス）」「中断」「開始と終了」など、無料で読めます
- **境界値分析**：上限・下限の「ちょうど」と「1つ外」を試す（上限1000文字なら、1000文字と1001文字）
- **同値分割**：同じ扱いになる入力をグループに分け、各グループから1つずつ試す
- **ペアワイズ（オールペア）法**：条件の組み合わせが多すぎるとき、「どの2つの条件の組み合わせも1回は出る」ように絞る（Microsoft の無料ツール PICT が有名）
