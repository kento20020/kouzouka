# 状態の定義（Step4：L4）

> 使い方：異常系を考える前に、状態を3層に分けて全部並べます。
> 上の層（アプリ全体）の変化は、下の層（画面・操作）の状態×イベント表では**列（イベント）**として扱います。

## チェックリスト

- [ ] 画面デザイン案の全パターン（読み込み中・0件・エラー…）が、どれかの状態に対応している
- [ ] 状態を true/false の組み合わせで持っていない（ありえない組み合わせが作れない）
- [ ] 各状態が「持つデータ」を書いてある（失敗時に入力内容と requestId を持っているか）
- [ ] 派生値を状態として持っていない
