# AIレビュー用プロンプト

> 使い方：状態×イベント表やユースケースを貼り付けて、AIに穴を探させます。
> AIの指摘は「候補」です。採用するかどうかは自分で判断し、採用したら表に反映します。

## 1. 状態×イベント表のレビュー

```text
あなたはソフトウェアの状態遷移設計とテスト設計のレビュアーです。
次の状態×イベント表をレビューしてください。

## 対象の機能
（機能の説明を1〜3行で）

## 状態×イベント表
（表を貼り付ける）

## 確認してほしいこと
1. 空欄、または「どうするか」が曖昧なマス
2. マスどうしの矛盾（例：あるマスでは入力を保持するのに、別のマスでは消している）
3. 足りない状態（例：再読み込み中、キャンセル済み）
4. 足りないイベント。次の観点で探してください
   - 2回起きたら／途中で止まったら／0件・1件・大量なら／遅かったら
   - 別の人なら／順番が違ったら／外部サービスが壊れたら／時間が経ったら
5. 二重実行・二重課金・データ消失・他人のデータが見えることにつながるマス

## 出力の形式
- 指摘ごとに「対象のマス」「問題」「なぜ問題か」「修正案」を表で出してください
- 重要度（高・中・低）をつけ、高いものから並べてください
- 推測で補った前提があれば、最後に「前提」として列挙してください
```

## 2. ユースケースのレビュー

```text
次のユースケース記述をレビューしてください。

（ユースケースを貼り付ける）

確認してほしいこと
1. 基本フローの各ステップについて、例外フローが抜けていないか
2. 例外フローの最後に「どこへ戻るか／どこで終わるか」が書いてあるか
3. 事後条件（成功時・失敗時）が十分か。二重保存・二重課金・中途半端な状態が起きないか
4. 粒度が混ざっていないか（画面のボタン名や API 名など、ユースケースのレベルより細かい情報が入っていないか）
```

## 3. シーケンス図のレビュー

```text
次のシーケンス図（Mermaid）をレビューしてください。

（シーケンス図を貼り付ける）

確認してほしいこと
1. 矢印1本ごとに、そこで通信が切れたらどうなるか
2. 端末が「失敗」と認識するが、サーバーでは成功している場合があるか。そのとき再送すると何が起きるか
3. 冪等キーの使い方は正しいか（再試行で同じキーを使っているか、サーバーは2回目に1回目の結果を返すか）
4. タイムアウト・再試行の回数・間隔は決まっているか
```
